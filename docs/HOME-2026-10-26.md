# DeX 主页：2026-10-26 验证

## 本轮方案与约束

使用者确认保持免 Root，并接受应用作为全屏默认 HOME、内部显示真正三星 DeX、按 HOME 返回 DeX。设置从软件入口打开，不保留悬浮设置按钮。退出统一使用三星任务栏最左侧菜单中的“退出 DeX”，恢复正常手机主页及其默认 HOME。

退出结束当前桌面会话，后台接收目标继续常驻、可发现、可重新连接；不要求 DeX 内应用一直运行。

## 设备与实现

- Samsung S20+ SM-G986U1，Android 13 / One UI 5.1，固件 `G986U1UESCHYC1`。
- Shizuku 用户服务 UID 2000；未使用 Root、未安装系统模块、未修改固件。
- 系统原生 DeX 使用双屏路径；实际桌面由三星服务及启动器生成。
- 最终版本 0.4.4 / versionCode 17，包名 `com.alkaidlab.dexlocal`。
- 手机 HOME 为 `.HomeEntryActivity`；它把 HOME 请求路由到物理显示 0 上的 `.DexHostActivity`。原主页为 `com.sec.android.app.launcher/.activities.LauncherActivity`。
- 本会话 DeX 逻辑尺寸适配到 2400×1080，主页窗口为全屏；不通过 Sunshine／Moonlight 编解码显示。
- HOME 返回桌面调用三星 `MultiWindowManager.minimizeAllTasks`，仅针对本服务当前拥有的 DeX 显示，再聚焦原生桌面。仅聚焦 HOME 任务不能收起三星自由窗口，已通过实际画面验证并修正。
- 自动进入前只清理三星手机启动器留存的 RecentsActivity 界面任务；不移除普通应用任务。窗口调整仅允许本应用在显示 0 上的任务。

## 实机结果

| 检查 | 结果 |
| --- | --- |
| 全屏与默认 HOME | HOME 角色为本应用，HOME Intent 解析到 HomeEntryActivity；实际全屏宿主为显示 0 上的 DexHostActivity，画面没有标题栏、浮窗边框或本应用设置悬浮按钮 |
| HOME 行为 | 在 DeX 打开显示设置窗口，向手机显示 0 发送 HOME 后，真实 DeX 返回其桌面 |
| 触控与任务栏 | 真实点击／滑动转发到 DeX；底部滑动可唤出三星原有的自动隐藏任务栏，未增加自制任务栏按钮 |
| 原生退出 | 从任务栏最左侧菜单点击“退出 DeX”后，系统 DeX 关闭、默认 HOME 恢复三星启动器，手机显示正常主页 |
| 尺寸恢复 | 退出后的 `wm size -d 2` 只显示原始 1920×1080，无本会话 override |
| 接收端常驻 | 原生退出前后 shell 接收进程 PID 14546 保持不变，配置仍为 enabled=true、automatic_home=true |
| 再次发现 | 未重新启动接收服务，直接打开三星 DeX，仍可找到 DeX Home 并出现连接确认 |
| 自动再次进入 | 确认后自动全屏显示 DeX，HOME 角色再次变为本应用，无需重新执行主页设置；native_exit_handled=1、mirror_active=true、listening=true、receiver_ready=true |

以上功能流程在最终安装的 0.4.4 实测。退出测试使用显示 0 的真实触控，经宿主转发到原生 DeX 菜单；重连仅重新打开系统三星 DeX 并确认，不重新启动软件或接收服务。重连后的诊断记录 injected_events=4、input_failures=0、error 为空。诊断顶层 message 可能保留先前窗口调整的提示，应结合 session.error 和当前窗口状态判断；当前宿主已核对在显示 0 全屏运行。

旧 0.3.3 也通过基本退出／重连流程，但不作为最终 HOME 路由实现的证据。最终版保留接收器单实例锁，可回收同 UID、同精确进程名的旧版自身服务；不终止 Shizuku／Stellar 管理器。

接收服务运行时暂时控制 Android 强制外屏桌面开关，避免它与三星原生 DeX 冲突。本机原值 1、本服务值 0；退出桌面保留该服务设置，完全停止接收服务时恢复原值。高刷实验设置在原生退出时已恢复，refresh_rate_mode=0，min/peak 恢复原空值。

## 60/120 帧实验

在真实 DeX 显示 2 上运行独立的持续动态绘制测试程序，使用它自己的 HWUI 帧计数及帧时间，不把主页刷新或重复显示当作新的源画面。

| 场景 | 时长 | 新绘制帧数 | 实际源绘制 FPS | 源 VSync 间隔中位数 |
| --- | ---: | ---: | ---: | ---: |
| 默认设置 | 20.205s | 1216 | 60.18 | 16.613ms |
| 请求 120Hz 后 | 20.295s | 1222 | 60.21 | 16.616ms |

请求后，DeX 仍仅公布 60Hz，用户首选模式读回 `-1 -1 0.0`，物理内屏的活动 SF 模式仍为 1080×2400、60Hz。两次结果没有实际提升，**本机 60 帧限制未解除**。

帧率样本来自 0.3.3 的相同接收／合成后端。测试程序是独立验证工具，不是本应用运行依赖；Sunshine 主机应用未运行。上述帧率不是编码帧率或输入到显示的端到端延迟。

## 证据与边界

原始设备图像、显示状态及诊断位于忽略目录 `work/home-validation/`，包含原生退出前后、再次发现和自动进入的证据。帧率原始数据在 `source-baseline/`、`source-high-request/`。

最终流程证据：`v044-settings.png`、`v044-home-key.png/json`、`v044-exit-menu.png`、`v044-native-exited.png`、`v044-rediscovered.png`、`v044-reconnected.png/json`。图片为设备原图，仅保存在本机，未打入源码交付。退出后的 HOME 为三星启动器，DeX displayId=-1，显示 2 无 wm size override。重连恢复 2400×1080 真正 DeX，内屏和源仍为 60Hz。

构建 `testDebugUnitTest lintRelease assembleRelease` 成功，13 项 JVM 测试通过，Lint 为 0 errors / 11 warnings。警告主要是本固件所需的反射接口、备份声明和中文字符串资源化。安装包签名与安装后字节另行校验，原 Sunshine Git 工作区保持干净。

构建与 JVM 检查不替代实机结果。尚未验证开机自动恢复、Shizuku 被停止后的完整恢复、长时间运行、其他机型及所有鼠标／键盘／输入法组合。当前只有接收服务实际存活且网络条件满足时保证目标待机；原生退出会结束桌面和其应用会话。
